# Literature Slide Writer

The reader of this deck is entering a research area they do not know. The deck
is how they will learn it: first the landscape (which problems the field is
working on), then each paper in one slide, then what is still open. They will
not read the papers first, so what the slides say has to be what the papers say.

Request: $ARGUMENTS

Defaults: index `./reference/index.md`; template `./slide/literature_review_template`;
deck `./slide/<area-slug>-literature`; English only. Build the Korean version
only when the user asks for it (`korean`, "한국어 버전도").

## How the work is divided

Three kinds of work, kept apart on purpose:

- **Per-paper agents** read one PDF each and write that paper's slide, figure and notes. They run in parallel and each touches only its own three files, so they cannot collide.
- **`scripts/deck.py`** does the bookkeeping: which papers are done, assembling the overview and the paper section from the index and the notes, building the PDF, finding slides that overflow. Anything a script can decide, it decides, so that 35 slides come out uniform.
- **You** (the main session) run the stages, write the open-problems section — the one part that needs a view across all papers — and review the built deck.

```
<deck>/
├── main.tex, Makefile, beamerthemepptblue.sty, fonts/     # from the template, unchanged
├── papers.json                  # manifest written by `deck.py prepare`
├── notes/<key>.json             # per paper: short title, one-line focus, stated limitations
├── images/<category>/<key>.png  # per paper: main figure, 600 DPI
├── sections/
│   ├── title.tex                # you
│   ├── overview.tex             # generated by `deck.py assemble`
│   ├── paper_summaries.tex      # generated by `deck.py assemble`
│   ├── papers/<category>/<key>.tex   # per paper: one frame
│   └── open_problems.tex        # you
└── sections-ko/                 # same layout, Korean (only on request)
```

`<key>` is the PDF's file name without `.pdf`; `<category>` is the category's
short name. Both come from `index.md`.

Commands below use:

```bash
PY=<repo-root>/.venv/bin/python          # created by ./setup.sh
DECK="$PY <this-skill-dir>/scripts/deck.py"
```

If `.venv` or XeLaTeX is missing, run `./setup.sh` in the repository root first
(it installs PyMuPDF and TinyTeX).

## Workflow

### 1. Prepare the deck

```bash
$DECK prepare reference/index.md --template slide/literature_review_template --deck slide/<area-slug>-literature
```

This copies the template (the template itself is never edited; an existing deck
is never overwritten), creates the folders, and writes `papers.json`. Read its
output:

- `todo` — papers that still need a slide. On a first run, all of them; on a re-run, only what is missing, so an interrupted job resumes where it stopped.
- `missing_pdf` — papers in the index with no PDF on disk. Tell the user; continue with the rest (run the download step to fill them in later).

Write `sections/title.tex`: `\title{Literature Review: <Research Area>}` and a
`\subtitle{...}` (for example the year range covered).

### 2. One agent per paper

For every key in `todo`, launch one agent with this prompt, filling in the
values from the paper's entry in `papers.json` (and the category's problem
focus from its `categories` list):

```
Read <this-skill-dir>/references/paper-agent.md and carry out the brief below its "---" line,
with these values for the <...> fields:
- repo: <repo-root>
- deck: <deck, absolute path>
- key / title / venue / year / arxiv_id / pdf
- category / category problem focus
- tex / image / notes
```

Launch them in parallel, about eight at a time, so the whole set finishes in a
few rounds without flooding the machine. The brief tells each agent to read the
PDF, crop the main figure with the `paper-figure-extractor` script and look at
the crop, write the frame, and write the notes file.

When a round finishes, run `$DECK prepare ...` again (same arguments): `todo`
now lists only the papers whose agent failed or left a file out. Relaunch
those. Read the agents' short reports for anything they were unsure about.

### 3. Assemble

```bash
$DECK assemble <deck>
```

Writes `sections/overview.tex` — the landscape slide (one row per category) and
one slide per category with its problem focus and its papers — and
`sections/paper_summaries.tex`, which pulls in the paper frames in index order.
Category names and problem-focus texts come straight from `index.md`; the
one-line description of each paper comes from its notes.

The landscape slide has little room per row: a category name and one short line.
By default the line is the first sentence of the problem focus, which is usually
too long. Write `<deck>/notes/_landscape.json` — `{"<category short name>": "<what
is at stake, at most 45 characters>", ...}` — and assemble again; the full
problem focus still appears on each category's own slide. If one of these reads
badly on the slide, fix it at the source (`index.md` or `notes/<key>.json`) and
assemble again, because the generated files are overwritten on every run.

### 4. Write the open problems

Read all `notes/*.json` (the `limitations` and `future_work` the papers state)
and look at the taxonomy as a whole. Identify 4–6 open problems from two sources:

- **Stated by papers** — a limitation or open direction that several papers name independently, or that one paper names and none of the others resolves.
- **Inferred from the landscape** — a gap visible only across papers: a problem no category addresses, or an assumption every paper in a category shares and none tests (the same languages, the same model scale, the same benchmark).

Each open problem must be tied to specific papers in the deck. If you cannot
name the papers that are the evidence, it is an opinion about the field, not a
finding from this literature — leave it out. Keep the two sources labelled: a
newcomer needs to know which statements they can cite to a paper and which are
your reading.

Write `sections/open_problems.tex` with one frame per open problem. Copy this
frame, spacing commands included:

```latex
\section{Open Problems}

\begin{frame}{<The open problem, as a short statement>}
  \papermeta{Stated by papers}   % or: Inferred from the landscape
  \footnotesize
  \begin{block}{What remains unsolved}
    \begin{itemize}\setlength{\itemsep}{0pt}
      \item ...
    \end{itemize}
  \end{block}
  \vspace{-2mm}
  \begin{block}{Why current approaches fall short}
    \begin{itemize}\setlength{\itemsep}{0pt}
      \item ...
    \end{itemize}
  \end{block}
  \vspace{-2mm}
  \begin{block}{Evidence}
    \begin{itemize}\setlength{\itemsep}{0pt}
      \item <Short title> (<Venue Year>): <what it shows or admits>
    \end{itemize}
  \end{block}
\end{frame}
```

The frame holds about nine lines below the title. Keep to one or two bullets in
the first two blocks and up to three under Evidence, each bullet at most 100
characters so that it stays on one line, and the frame title at most 50
characters. The checker enforces these.

### 5. Build and check

```bash
$DECK check <deck>
```

It checks every paper slide (one frame, its own figure, Problem and Method
blocks, bullet count and length, unescaped LaTeX characters, figure
resolution), builds `slides-en.pdf` with `make`, and inspects the PDF for slides
whose content runs past the bottom. Work through the report:

- `build.latex_errors` — the build stopped. The message names the line; fix that file and run again.
- `slide_issues` — per paper. Fix the frame yourself if it is a small text change; if a figure is wrong or a slide is poor, relaunch that paper's agent.
- `overflowing_slides` — shorten the text on that slide (tighter bullets first; the figure's `height=` only as a last resort). For an overview slide, shorten the text in `index.md` or the notes and assemble again.

Repeat until the report says `"ok": true`.

### 6. Look at the deck

Checks cannot see a bad crop or a lopsided slide. Render the deck as contact
sheets and read them:

```bash
$DECK sheets <deck> --out <deck>/build/sheets-1      # a new folder each time
```

Look for: a figure that is cut off, includes its caption or body text, or is
too small to read; a slide with far more or far less text than its neighbours;
wording that differs in style from one slide to the next. Fix what you find and
rebuild. Also read the `category_fit` field across the notes: where an agent,
having read the whole paper, doubts the category, report it to the user — do
not move the paper yourself, since folders, index and slides would all have to
change together.

### 7. Korean version (only if asked)

Read `references/korean.md` and follow it. It translates the finished English
slides into `sections-ko/`, then builds and checks `slides-ko.pdf`.

### 8. Report

```
slide/<name>/slides-en.pdf — <N> slides: overview (<K> categories), <P> papers, <M> open problems
Papers without a slide: <titles and why — missing PDF, agent could not extract a figure>
Figures adjusted by hand: <count>; used a table instead of a figure: <papers>
Category doubts raised by the per-paper agents: <paper → reason>
Unsure: <anything an agent could not confirm in its PDF>
```

Leave out the lines that are empty. Do not commit or push the deck unless the
user asks.
